# mosi-asr v0.1.0

Date: 2026-09-29

首个发布版本. mosi-asr 把 Moss API 的语音识别能力搬到命令行, 让日常的会议录音, 访谈, 播客和课程回放可以直接转成文字: 交付物是单个 Go 二进制, 没有任何运行时依赖.

转写内容需要上传到服务端处理, 涉密音频请自行评估后再使用.

## Highlights

- 三种调用方式都能用: 同步请求适合短音频, SSE 流式边转写边出字, 异步任务配 `async=true` 适合长录音, 客户端按服务端返回的 `retry_after` 轮询任务接口.
- 说话人识别开箱可用: `-d` 启用后按 `S01`, `S02` 分行输出, 相邻同说话人的碎句会按间隔自动合并, 不再是逐句碎成一地.
- 结果格式覆盖读和用: `txt` 供阅读, `srt` 直接当字幕, `json` 保留服务端原始响应交给脚本, `md` 便于归档.
- 批量与管道都顺手: 目录, 通配符可以一次传入, 参数写在文件名前后都认, `-o -` 让结果直接进管道.
- 配置集中且能平滑升级: `~/.config/mosi-asr/config.toml` 带版本号和自动迁移, 密钥支持配置文件与环境变量两级回退.

## Upgrade Notes

首个发布版本, 不存在需要迁移的旧版本与旧配置.

1. 安装. 从 GitHub Release 下载对应平台的归档并解压到 PATH 中的目录:

   ```shell
   tar -xzf mosi-asr-0.1.0-macos-aarch64.tar.gz
   install -m 755 mosi-asr /usr/local/bin/mosi-asr
   ```

   或者用 Go 直接装:

   ```shell
   go install github.com/azazo1/mosi-asr/cmd/mosi-asr@latest
   ```

2. 准备 API Key. 到 Moss 平台创建 Key, 然后二选一: 写进配置文件, 或者放进环境变量:

   ```shell
   mosi-asr config init          # 生成 ~/.config/mosi-asr/config.toml
   export MOSS_API_KEY=你的Key
   ```

   密钥只放环境变量时不要把 Key 提交到任何仓库; 配置文件的权限会被收紧到 `0600`.

3. 验证安装:

   ```shell
   mosi-asr version
   mosi-asr config show          # 确认配置路径与密钥来源
   mosi-asr 一段录音.m4a         # 结果写到同目录的 录音.txt
   ```

   `mosi-asr config show` 打印的密钥是脱敏预览, 可以放心贴出来排查问题.

## Features

**转写通道**

- `POST /v1/audio/transcriptions` 的三种模式都覆盖: 同步 multipart, `stream=true` 的 SSE 增量输出, `async=true` 的异步任务.
- 异步任务使用 `GET /v1/audio/tasks/{task_id}` 查询, 并优先采用服务端建议的轮询间隔.
- 本地文件走流式上传, 512 MB 的文件不会整体读进内存; 请求体长度预先算准, 避免退化成 chunked 传输导致网关拒收.
- 输入源支持本地文件, 公网 URL 与 `file_id`, 三者互斥并会在本地提前拦下冲突组合.

**说话人识别与热词**

- 启用说话人识别, 流式输出或传入热词时, 未显式指定模型会自动选用 `moss-transcribe-diarize-pro`.
- 显式指定普通模型又要求流式或热词时, 本地直接报错并说明原因, 不必等服务端返回 400.
- 热词最多 20 个, 每个不超过 30 个字符, 数量与长度在本地先校验.

**输出**

- `txt`: 按说话人分行, 相邻同说话人的分段按 `merge_gap_seconds` 合并; 中英文混排时只在需要的地方补空格.
- `srt`: 带时间轴的字幕, 说话人写进字幕正文.
- `json`: 透传服务端原始响应, 字段不丢失.
- `md`: 每条发言一段, 可带说话人与时间范围.
- `text`: 服务端返回的原始整段文本.
- 默认输出到音频同目录同名文件, 也可用 `--dir` 统一收拢, `-o -` 直接打印到终端.
- 流式叠加结构化格式时, 增量文本改走标准错误, `-s -f json -o -` 的输出仍是干净的 JSON.

**命令行体验**

- 参数可以写在文件名之后, 全局参数可以写在子命令之前或之后.
- 目录与通配符会展开成批量任务, 隐藏文件不参与展开, 逐个文件报进度并在结尾汇总失败数量.
- `task` 子命令可以事后查询异步任务并直接导出成任意格式.

**配置与日志**

- 配置文件读取 `~/.config/mosi-asr/config.toml`, 可用 `--config` 或 `MOSS_ASR_CONFIG` 覆盖.
- 配置带 `version` 字段与独立的迁移模块, 没有版本号的老配置加载时自动升级, 未知字段会给出拼写提示.
- 密钥来源顺序为 `api.api_key` 到 `api.api_key_env` 再到 `MOSS_API_KEY`, `config show` 只输出脱敏预览.
- 日志基于 `log/slog` 写入标准错误, 覆盖调用阶段, 耗时, 上传进度与接口错误, 标准输出始终只承载转写结果.
- 接口错误会附带对应错误码的中文处理建议, 并对 408, 425, 429 与 5xx 做指数退避重试, 遵循 `Retry-After`.

**构建与分发**

- 单 Go 二进制, 无运行时依赖.
- CI 在 Linux, macOS, Windows 的 x86_64 与 aarch64 六个原生 runner 上分别构建与测试, 归档前运行 `--version` 冒烟校验版本注入是否生效.
- 发布构建的版本号自动生成: 恰好停在 tag 上时显示该 tag, 非 tag commit 追加 7 位短 hash, 工作区有未提交改动时改用 `^` 分隔, 日常开发构建显示 `dev-build`.
- 仓库自带 `scripts/mock-server.py` 离线模拟服务, 不触碰真实接口即可跑通从配置读取到结果落盘的完整链路.

## Known Limitations

- 官方限制: 单文件最大 512 MB, 流式输出与热词只支持多说话人模型, `stream` 与 `async` 不能同时使用.
- 支持格式为 AAC, AMR, FLAC, M4A, ALAC, MOV, MP3, MP4, MPG, OGG, OPUS, WAV, WebM, WMA; 其他扩展名会给出提示但仍会尝试上传, 是否接受由服务端决定.
- 长音频会按 `transcribe.auto_async_over_mb` 阈值自动切换成异步任务, 该行为可以用 `--sync` 关掉.
- 说话人标识是服务端给出的 `S01` 这类编号, 无法在客户端绑定到具体人名.
- 转写质量与服务端模型和网络状况相关, 客户端只负责参数与结果的搬运.
